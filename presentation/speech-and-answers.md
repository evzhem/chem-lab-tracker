## 2. Текст доклада (сжатая версия по слайдам)

**Слайд 1.** Добрый день. Тема моей работы — приложение-справочник по химии ChemLab Tracker.
Я сделал приложение для телефона, которым можно пользоваться на уроке и в лаборатории:
без интернета, без регистрации и без рекламы.

**Слайд 2.** Проблема: обычные справочники — это книги или сайты, которые часто недоступны
без интернета. Цель — собрать всё нужное в одно приложение на телефоне. Работу я разбил
на пять задач: данные, интерфейс, разделы, хранение данных на устройстве и автоматическая
сборка. Оценивал результат по четырём критериям: работа офлайн, установка на телефон,
данные пользователя остаются у него, разделы открываются мгновенно.

**Слайд 3.** В приложении девять экранов: поиск реакций, таблица Менделеева с карточками
элементов, таблица растворимости, калькулятор молярной массы, справочные схемы, дневник
опытов, безопасность, карточка опыта и настройки.

**Слайд 4.** Вот как это выглядит на телефоне: главный экран, таблица Менделеева, таблица
растворимости и дневник опыта.

**Слайд 5.** Стек: React — интерфейс из компонентов; Vite — сборка; Tailwind — стили;
React Router — навигация; vite-plugin-pwa — офлайн-режим; Capacitor — сборка APK;
localStorage — хранение данных на устройстве. Сервер и база данных не нужны: справочные
данные не меняются, а записи пользователя хранятся локально.

**Слайд 6.** Вот главная схема проекта. Сверху — данные, они не зависят от интерфейса.
Из них собираются экраны. Общая логика вынесена в отдельную папку, чтобы не дублировать код.
Внизу — то, чем всё заканчивается: хранилище браузера, service worker и сборка под Android.

**Слайды 7–10.** Дальше по коду: точка входа, где подключаются тема и проверка обновлений;
маршруты — почему адреса с решёткой; каркас Layout — общее меню для всех экранов и хранилище
данных.

**Слайды 11–14.** Самые интересные части: как данные превращаются в интерфейс.
Поиск реакций — привел запрос к одному виду, заменил индексы на цифры и ищу по всем веществам.
Калькулятор молярной массы — разбор формулы на токены, рекурсия для скобок и отдельная
обработка гидратов. Таблица Менделеева строится циклом, а не расставлена руками.
Дневник хранится в localStorage с версией ключа и проверкой данных.

**Слайды 15–17.** Оформление и удобство: темы через CSS-переменные, масштаб таблиц через em
(пробовал CSS zoom — «съезжали» закреплённые заголовки).

**Слайды 18–19.** Проверка обновлений. При сборке создаётся файл с версией и списком изменений.
При запуске приложение тихо его запрашивает и сравнивает версии по числам — если сравнивать
строками, «1.10» окажется меньше «1.9». Если версия новее, появляется карточка с изменениями
и кнопками «Обновить» и «Позже».

**Слайд 20.** Сборка автоматическая: один сценарий публикует сайт, второй собирает APK
для Android. Один и тот же код, разные настройки путей.

**Слайды 21–22.** Мелочи для телефона: отступы под «чёлку», поля ввода 16 пикселей,
пустые состояния, линтер перед сборкой. Итог: приложение работает как сайт и как приложение
для Android, данные хранятся у пользователя. Главный вывод: сложнее всего не вёрстка,
а связи — где хранить данные и как их обновлять, не теряя записи пользователя.

## 3. Ответы на вероятные вопросы

**1. Почему React, а не обычный HTML и JavaScript?**
React собирает интерфейс из независимых компонентов. Мне нужно было 9 экранов с общими
частями: меню, шапка, таблицы. В React я описываю их один раз и переиспользую, а состояние
интерфейса меняется автоматически — не нужно вручную перерисовывать DOM.

**2. Что такое хуки, которые ты используешь?**
Это функции React: `useState` хранит состояние (например, выбранный элемент таблицы),
`useEffect` выполняет побочные действия (запись в localStorage, запрос версии),
`useMemo` считает вычисления только при изменении входных данных — например, результат
разбора формулы. `useContext` даёт доступ к общим данным, например к теме.

**3. Что такое «провайдер» и зачем их два?**
Провайдер — компонент, который отдаёт данные всем вложенным экранам без передачи пропсов
через каждый уровень. У меня два: тема (тёмная/AMOLED) и проверка обновлений. Любой экран
получает их через хуки.

**4. Почему HashRouter, а не обычные адреса?**
Сайт размещён на GitHub Pages, где нет серверной настройки. При обычных путях перезагрузка
страницы дала бы ошибку 404, потому что сервер не знает про вложенные адреса. С решёткой
адрес целиком обрабатывает браузер — приложение работает корректно.

**5. Где хранятся данные и почему не база данных?**
Справочные данные (элементы, реакции) лежат прямо в коде — они не меняются, их не нужно
искать по сети, поэтому всё работает офлайн и мгновенно. Данные пользователя (дневник опытов,
настройки) хранятся в localStorage браузера — на устройстве, без сервера и регистрации.

**6. Что произойдёт, если пользователь очистит данные браузера?**
Записи дневника удалятся — они принадлежат устройству. Я это предусмотрел: в настройках есть
предупреждение и подтверждение перед очисткой, а в планах — экспорт дневника в файл.

**7. Что будет, если структуру записи придётся изменить в новой версии?**
Ключ хранилища содержит версию (`chemlab-experiments-v1`), а при чтении каждая запись
проходит через функцию нормализации, которая достраивает отсутствующие поля. Поэтому старые
записи после обновления продолжают открываться.

**8. Как работает поиск реакций, если уравнения записаны с индексами?**
Я привожу и базу, и запрос к одному виду: заменяю нижние индексы (₂, ₃) на обычные цифры
и убираю пробелы. Поэтому `H2O` и `H₂O` находят одно и то же. Плюс запрос делится по «+»:
если введено несколько веществ, ищется уравнение, где встречаются все.

**9. Как считается молярная масса для формулы со скобками?**
Формула разбирается на токены (элементы и числа). Встретив скобку, программа рекурсивно
вызывает ту же функцию для содержимого и умножает результат на коэффициент после скобки —
так правильно считается Fe2(SO4)3.

**10. Что такое гидрат и как он обрабатывается?**
Это кристаллогидрат, например медный купорос CuSO4·5H2O. Точка здесь — разделитель, а не
десятичная запятая. Поэтому я нормализую знаки «·», «•», «×» и точку в специальный символ
и учитываю коэффициент группы воды.

**11. Почему для масштаба таблиц не использован zoom?**
Пробовал CSS-свойство `zoom`: у меня есть закреплённые заголовки строк и столбцов, и они
смещались при прокрутке. Поэтому масштаб реализован через размер шрифта контейнера и размеры
в em — это работает одинаково во всех браузерах.

**12. Что такое PWA и service worker?**
PWA — сайт, который устанавливается на телефон как приложение. Service worker — фоновая
программа браузера, которая кэширует файлы, поэтому приложение открывается без интернета.
Установка идёт из браузера, отдельно распространять ничего не нужно.

**13. Как делается APK из веб-приложения?**
Через Capacitor: он переносит собранную веб-часть в Android-проект, где она открывается
во встроенном браузере. Дальше обычная сборка Gradle — получается устанавливаемый файл APK.
Код при этом один: и для сайта, и для Android.

**14. Как проверяются обновления и почему сравнение версий — отдельная функция?**
При сборке формируется файл `version.json` с номером версии и списком изменений. При запуске
приложение его запрашивает и сравнивает со своей версией. Сравнивать нужно по числам,
а не как строки: иначе «1.10» окажется меньше «1.9», потому что символ «1» меньше «9».
Поэтому версия делится на части и сравнивается по порядку.

**15. Что происходит, если интернета нет?**
Проверка обновлений завершается ошибкой, которую я перехватываю — приложение просто работает
дальше, никаких сообщений и «крутилок». Все справочные данные уже загружены вместе
с приложением.

**16. Как ты проверял, что всё работает?**
Линтер `oxlint` — ищет забытые переменные и ошибки; сборка проекта — проверяет, что всё
компилируется; отдельно проверял открытие всех девяти экранов и переключение темы; логику
обновлений проверял, подменяя версию на сервере — окно должно появляться только когда версия
действительно новее.

**17. Что было самым сложным?**
Разбор формулы (парсер) и совместимость данных: нужно было продумать, что делать, если
запись создана старой версией приложения, и сделать поиск устойчивым к разным форматам ввода.

**18. Что можно улучшить?**
Экспорт дневника в PDF, добавление своих реакций, избранные элементы и версия для планшета
с двумя колонками.

## 5. Словарь терминов (на случай вопроса «объясни простыми словами»)

- **Компонент** — самостоятельный кусочек интерфейса (кнопка, экран, карточка).
- **Хук** — функция React, дающая компоненту состояние или доступ к общим данным.
- **Провайдер / контекст** — способ передать данные сразу всем экранам, не переписывая их
  через каждый уровень.
- **SPA** — приложение из одного HTML-файла, где экраны меняются без перезагрузки страницы.
- **PWA** — сайт, который можно установить на телефон и который работает офлайн.
- **Service worker** — фоновая программа браузера, кэширующая файлы для офлайн-работы.
- **localStorage** — встроенное хранилище браузера на устройстве пользователя.
- **Токенизация** — разбиение строки (формулы) на отдельные значимые части.
- **Рекурсия** — приём, когда функция вызывает саму себя (используется для скобок).
- **CI (непрерывная интеграция)** — автоматическая сборка и публикация проекта сервером
  после изменений.
